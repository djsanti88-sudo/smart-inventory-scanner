## Notable non-finding worth flagging to the owner

Claim #3 (idempotencyKey never regenerated on retry) is the one claim in this audit that is **not
backed by a structural guard or a targeted test** — it currently holds only because no code path
does the regeneration, which is exactly the shape of risk the tire-corpus defect warned about (a
property that holds today by omission, not by design enforcement). Recommend adding a narrow
regression test that asserts a queue item's `idempotencyKey` is byte-identical before and after
`retrySync()`/a failed-then-retried `drainCloudOnce` pass, so this doesn't silently regress.
