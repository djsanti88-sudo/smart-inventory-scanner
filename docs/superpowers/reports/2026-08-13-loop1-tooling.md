## Summary

The single most dangerous finding is **TL-1**: `scripts/model-bakeoff.mjs` reads the app's live
`OPENAI_API_KEY`/`GEMINI_API_KEY` straight out of `.env.local` and, on a bare `node
scripts/model-bakeoff.mjs` with no flags, fires 50 live paid calls (5 models, including GPT-5 and
Gemini 2.5 Pro, across 10 tire codes) against `api.openai.com` and
`generativelanguage.googleapis.com` before printing anything. There is no `--live` opt-in, no
confirmation gate, no owner-approval check of any kind — it is indistinguishable at a glance from
a free local analysis script. It is wired into neither `package.json` nor
`docs/COMMANDS.md`'s PAID/LIVE table, so the project's own documented list of billed scripts is
incomplete. This matches, almost exactly, the incident already recorded in project memory ("GPT
mini bakeoff 2026-07-26... caused real owner charges") — the offending script class survived that
incident and is still live in the repo today.

Two more findings follow the same "looks maintained, silently destroys the real artifact" shape
the CONTEXT section named: `build-knowledge-db.mjs` (TL-3) unconditionally deletes the committed
knowledge DB before validating that new source data loaded, and only warns (never fails) if it
didn't, so a bad LFS checkout or corrupt JSON produces an empty DB reported as success.
`build-retail-knowledge.mjs` (TL-4) is the sibling of `build-tire-knowledge.mjs`'s already-fixed
shrink bug — it still has no `MIN_RETAINED_FRACTION`-style guard at all, so a truncated or
partial `retail_off.jsonl` silently replaces the ~4M-row retail index with a much smaller one.
`import-retail-turso.mjs --force` (TL-5) can DROP the live 4.13M-row production Turso retail table
and reimport from a stale local file with zero pre-drop size comparison. By contrast, the pilot
scripts (`pilot-apply-corpus.mjs`, `pilot-apply-turso.mjs`) and the tire-db-repair promotion
pipeline (`10_promote_execute.mjs`) are the gold standard here — heavily guarded, additive-only or
confirm-gated, fingerprinted, and reviewed — worth using as the template when fixing TL-3/4/5.
Orphaned-test-runner protection (TL-6) is currently sound: all 10 vitest-excluded suites are wired
into `proof-all.mjs`'s `NODE_TEST_SUITES`, though the pairing is still hand-maintained with no
automated cross-check.
