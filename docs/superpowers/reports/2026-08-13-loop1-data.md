# Loop 1 — Data/Catalog/Sync/Knowledge section — defect hunt

Date: 2026-08-13
Scope: `src/services/db/**`, `src/services/catalog/**`, `src/services/reconcile/**`,
`src/services/csvImport.ts`, `src/services/csvExport.ts`, `src/services/columnIntelligence.ts`,
`src/services/sessions/**`, `src/server/business/**`, `src/server/share/**`,
`src/server/tire-knowledge/**`, `src/server/retail-knowledge/**`, plus the corpus-generator
scripts under `scripts/` that write into those two `src/server/*-knowledge/` directories.
Method: read-only static review, no edits, no writes to any DB. `.next/` excluded from every
search.

## Summary of what was checked and found sound

`firestore.rules`, `firebaseSyncTarget.ts` + `firebaseSyncSafety.ts` (the idempotent-apply
transaction), `businessDataLoader.ts`/`boundedRead.ts`, `provisioning.ts`, `shareTokenStore.ts`,
`csvImport.ts`/`csvExport.ts`, and the reconcile adapters (`universalAdapter.ts`,
`dollarVariance.ts`) all show careful, already-reviewed tenant scoping (businessId derived from
Firestore path, never trusted from client payload alone), cost/price stripping before any network
call, and CSV-injection/control-character sanitization. No numeric coercion of barcode-shaped
fields was found in this section (`Number()`/`parseInt()` calls that exist are all confidence
scores or env-var parsing, never applied to a barcode/SKU string). **These are NOT re-verified as
passing tests** beyond reading the code — see Traps note below on which suites actually execute.

The one finding below is a genuine, high-value invariant gap: exactly the shape the task brief
flagged as worth hunting for (a generator sibling of the tire generator's pre-2026-08-12 bug).

Add a `retail` counterpart to `corpusDrift.test.ts` (or extend it) so `npm run test:corpus-drift` actually exercises this invariant instead of just the tire half. ## Lower-confidence / not pursued further (time-boxed)

- `scripts/corpus-purge.mjs`, `scripts/pilot-apply-corpus.mjs`, `scripts/phase1-enrich-build.mjs`
  also `writeFileSync` into corpus-adjacent JSON without a shrink guard, but these are one-off
  manual/pilot scripts, not a documented `npm run` regen path — lower likelihood of accidental
  re-run than the retail generator. Worth a follow-up pass if the owner wants full coverage of
  every write path under `scripts/`.
- Firebase Auth is a single global user pool; `POST /api/businesses/members` looks up
  `getUserByEmail` and, if that email already has an account (possibly created under a completely
  different, unrelated business), attaches a NEW membership under the inviting business without
  any cross-check. This only grants the invited email access to the inviter's own business (the
  inviter's deliberate action), so it does not appear to be a tenant-isolation leak in the
  direction that matters — flagged for awareness, not filed as a defect, given time constraints.

## Traps honored
