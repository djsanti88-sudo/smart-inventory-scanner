# Fetch V2.3 "trusted door + accurate barcode" - design (2026-07-05, owner-approved, PRE-TESTED)

Owner rules: (1) ONE good source (major retailer, vetted barcode DB, reputable vendor) with the
EXACT code = VERIFIED. (2) Weaker evidence = NEEDS REVIEW / SUGGESTED - counted, never auto-counted.
(3) "Accurate barcode" - a number merely APPEARING near a product is not evidence; it must sit in a
barcode position. Baseline to beat: v2.2 (34 verified / 0 wrong / canaries 10/10 / ~410cr).

## Pre-test results that shaped this spec (simulated on v2.2 campaign data + live probes)
- Naive vetted-host single-source verify: 37 flips, 35 right, **2 WRONG** (recycled codes where
  go-upc holds the other product) -> REJECTED as-is.
- Amended with the free-Brave agreement fence: both wrongs provably blocked (Brave returns garbage
  for them), 4/5 sampled rights pass. Projected verifies ~62 vs 34, wrongs stay 0.
- Canary exposure to vetted hosts across the whole campaign: zero.

## Components
1. **Barcode-label context (accuracy core).** A code match counts as barcode evidence ONLY in:
   JSON-LD gtin/upc/ean fields; a table/dt row labeled UPC/EAN/GTIN/Barcode (+es/de variants);
   a keyed API; or text/snippet within ~24 chars of such a label. Bare numbers in prose stop being
   evidence (page_text weak tier requires label context now).
2. **Negative-context blacklist.** A match adjacent to case/MLS/listing/order/invoice/phone/zip/
   P.O./item# is affirmatively disqualified regardless of anything else.
3. **Vetted-host single-source verify (the pre-tested rule).** VERIFY when ALL hold:
   host in TRUSTED_DB_HOSTS (go-upc, upcitemdb, eandata, barcodelookup, barcodespider) OR existing
   strong-commercial tier; exact code in a labeled/structured position (never detail_table_echo);
   identity passes the full name firewall; no not-found/junk flags; no sibling/conflict; AND >=1
   free Brave result whose title AGREES with the identity (identityRelation "agree"; the fence).
   Confidence 0.8. Snippet 3-host consensus verify STAYS (owner: agreeing vendors are good sources),
   with label-context snippets outranking bare-number snippets (bare ones count only toward
   consensus, never alone).
4. **Wider free door.** patternUrls picks per code type from the full 15-site pool (EAN-13 ->
   ean-search/eandata first; UPC-12 -> go-upc/upcitemdb), up to 4 URLs, early-stop on first clean
   hit. Door findings count toward consensus pairs.
5. **Notation lenses in the conflict guard.** Multi-size titles = size-ambiguous (not conflict);
   flotation/XL/speed-suffix normalization moves from the graders into identityRelation. Target:
   most of the 25 review rows collapse to their correct identities.
6. **Ladder handoff.** scripts/fetchv2-ladder-handoff.json: every review/receipted code with its
   best candidate + sources, so the next step confirms instead of searching.

## Safety gates (all must pass before tag fetchv2-2.3)
- All 10 canaries live-refused; the two known wrong-flip codes (092971135485, 769382907580) must
  NOT verify; zero wrong auto-counts on the full re-run; suite + tsc + Playwright green.
- Live campaign per owner batch protocol: batches of ~10, grade, fix, re-run that batch.
- Must beat v2.2: more verifies, fewer review rows, wrongs still zero, spend same envelope.
- v2.2 tag = rollback; commit per task; no push without owner word.
